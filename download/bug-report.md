## 🐛 Найденные и исправленные баги

### BUG-1: Combo Chain не работала (критичный)

**Симптом:** Игрок открывал сундуки подряд, но индикатор COMBO в UI всегда показывал `×0`. Комбо-бонус к качеству лута не начислялся.

**Причина:** В `completeOpening` (store.ts) после успешного открытия сундука поле `combo` в `set()` вообще не обновлялось — оно оставалось `{ count: 0, lastOpenAt: 0 }`. Таймаут в `checkEvents` сбрасывал комбо каждые 10 секунд, но инкремента не происходило.

**Тесты, выявившие баг:**
- `completeOpening + Combo > BUG: combo.count должен увеличиваться после открытия сундука`
- `completeOpening + Combo > комбо должно расти с каждым новым открытием`

**Исправление:** Добавлен блок в `completeOpening`:
```ts
combo: {
  count: Math.min(COMBO_MAX, state.combo.count + 1),
  lastOpenAt: Date.now(),
},
```

**Файл:** `src/lib/game/store.ts:705-710`

### BUG-2: Баланс подземелья инвертирован (критичный)

**Симптом:** С каждым новым этажом подземелья HP врагов УМЕНЬШАЛСЯ, а награды тоже УМЕНЬШАЛИСЬ. Игроку было выгоднее оставаться на 1-м этаже.

**Причина:** В `config.ts`:
```ts
export const DUNGEON_HP_MULT_PER_FLOOR = 0.8;     // ❌ HP ×0.8 за этаж
export const DUNGEON_REWARD_MULT_PER_FLOOR = 0.6; // ❌ награда ×0.6 за этаж
```
Комментарий гласил «линейный рост», но множители < 1 давали экспоненциальный спад. К 10 этажу: HP ×0.134, награда ×0.06 — абсолютно неинтересно играть.

**Тест, выявивший баг:**
- `balance sanity checks > BUG: HP и награды должны РАСТИ с этажом (множители > 1)`

**Исправление:**
```ts
export const DUNGEON_HP_MULT_PER_FLOOR = 1.12;    // ✅ +12% HP за этаж
export const DUNGEON_REWARD_MULT_PER_FLOOR = 1.20; // ✅ +20% наград за этаж
```
Баланс: этаж 5 = 1.57× HP / 2.07× наград, этаж 10 = 2.77× HP / 5.16× наград — герой с сет-бонусами проходит.

**Файл:** `src/lib/game/config.ts:716-722`

### BUG-3: Дублирующиеся ключи в object literals (code smell)

**Симптом:** В объектах Zustand-стейта поля дублировались — JS оставлял только последнее значение, но это создавало путаницу и было источником потенциальных багов при будущих правках.

**Причина:** Несколько мест в store.ts содержали одинаковые ключи в `set({...})` и `partialize`:

| Локация | Дубликат |
|---|---|
| `prestigeReset` (1272-1273) | `combo: { count: 0, lastOpenAt: 0 }` × 2 |
| `partialize` (1581-1582) | `combo: s.combo` × 2 |
| `migrate` (1527-1530) | `if (!s.combo) s.combo = ...` × 2 |
| `migrate` (1528-1531) | `if (s.ultCooldownUntil === undefined)` × 2 |

**Исправление:** Все дубликаты удалены.

**Файл:** `src/lib/game/store.ts`

### BUG-4: Дублирующийся useEffect для visibilitychange (производительность)

**Симптом:** В `page.tsx` было два одинаковых `useEffect` для прослушивания `visibilitychange` — браузер регистрировал два слушателя и диспатчил событие дважды при каждой смене видимости вкладки.

**Причина:** Код размножен копи-пастой (строки 165-173 и 187-192 в `page.tsx`).

**Исправление:** Второй дубликат удалён.

**Файл:** `src/app/page.tsx:187-192` (удалено)

### BUG-5: Уродливая SVG-отрисовка руки рыцаря с мечом (визуальный)

**Симптом:** В окне боя (`AutoBattle.tsx`) рука рыцаря выглядела как «какой-то ужас» — неанатомичные формы, клинок меча рос из руки под странным углом, руки были нарисованы примитивно.

**Причина:** Старый SVG использовал viewBox `0 0 100 200`, рука была нарисована одной криволинейной траекторией без структуры; меч был привязан к кисти под углом 15° через `transform="rotate(15 80 162)"`, что создавало визуальный разрыв между рукой и оружием.

**Исправление:** Полная перерисовка SVG в готическом стиле с детализацией:

| Элемент | Детали |
|---|---|
| **Наплечник** | 2 эллипса (внешнее кольцо + купол), 3 шипа, 3 заклёпки, блик сверху |
| **Плечо** | Сегментированный латный рукав с 3 линиями сочленения пластин |
| **Локоть** | Двойной эллипс с шипом и бликом |
| **Предплечье** | Трапециевидная пластина с 3 горизонтальными рёбрами |
| **Кисть** | Манжета + основная пластина кулака + 4 линии пальцев + большой палец |
| **Меч** | Бронзовое навершие с кабошоном, кожаная рукоять с обмоткой крест-накрест, готическая гарда с загнутыми концами и аметистом в центре, длинный клинок с долом (кровостоком), блик, готическая гравировка (кровавый крест с рубином), руна, капля крови на острие |
| **Градиенты** | `bladeGrad` (сталь), `armorGrad` (броня), `pauldronGrad` (наплечник) — три линейных/радиальных градиента для объёма |

**Анимация удара** переработана на 5 ключевых кадров:
```
0%   → -8°   (rest)
22%  → -28°  (замах назад)
50%  → +26°  (удар вниз-влево к врагу)
72%  → -4°   (отскок)
100% → -8°   (rest)
```
Длительность: 450 мс (было 250 мс) — более весомый удар.

**Дополнительно:**
- **След клинка** — белая дуга с красным glow-слоем, появляется только в момент удара (50% анимации), pathLength-анимация Framer Motion
- **Искры** — 5 белых частиц разлетаются от точки удара
- **Кровавые частицы** — увеличено количество с 6-8 до 8-12, увеличен разброс
- **Drop-shadow** на руке — красное свечение во время удара

**Файл:** `src/components/game/AutoBattle.tsx:161-340`

## 🔧 Структура тестовой инфраструктуры

```
tests/bun/
├── setup.ts          # Mock localStorage, navigator, requestAnimationFrame
├── helpers.ts        # freshStore(), giveKeys(), giveMoney(), setEnemiesKilled(), setHeroLevel()
├── store.test.ts     # 43 теста для zustand-стейта (кликер, сундуки, бой, престиж, экипировка)
├── items.test.ts     # 8 тестов для генератора 1000 предметов
└── balance.test.ts   # 12 тестов для балансных констант и формул

bunfig.toml           # preload = ["./tests/bun/setup.ts"]
```

Тесты используют:
- **bun:test** — встроенный тестовый раннер Bun
- **localStorage mock** — для Zustand persist middleware
- **Deterministic setup** — `freshStore()` сбрасывает стейт перед каждым тестом
- **TypeScript path aliases** — `@/lib/game/*` работают через относительные импорты
